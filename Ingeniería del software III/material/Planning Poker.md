# ✨ **Scrum y Planning Poker: Guía Completa para Principiantes** ✨

**Contexto Adaptado a Nicaragua 🇳🇮**

---

## **1. ¿Qué es Scrum?**

**Definición**: Scrum es un método ágil para gestionar proyectos complejos, dividiéndolos en etapas cortas (*sprints*) con entregas constantes.

**Analogía**:

> Imagina organizar una **fiesta de cumpleaños**:
>
> - **Sprint**: Planear cada detalle en 2 semanas
> - **Roles**: Tú (Product Owner), un amigo coordinador (Scrum Master), y los invitados que ayudan (Equipo).

---

## **2. Componentes Clave de Scrum**

### **Roles**

| **Rol**                | **Responsabilidad**                            | **Ejemplo en Nicaragua**                                |
| ---------------------------- | ---------------------------------------------------- | ------------------------------------------------------------- |
| **Product Owner (PO)** | Define qué se hace y prioriza.                      | Decide que una app de facturación cumpla con la DGI primero. |
| **Scrum Master (SM)**  | Facilita el proceso y quita obstáculos.             | Resuelve problemas con proveedores de internet.               |
| **Equipo Dev**         | Construye el producto (programadores, diseñadores). | Desarrolla una app para caficultores de Matagalpa.            |

### **Eventos**

| **Evento**          | **Duración** | **Propósito**                                                 |
| ------------------------- | ------------------- | -------------------------------------------------------------------- |
| **Sprint Planning** | 2-4 horas           | Planificar tareas para el sprint.                                    |
| **Daily Standup**   | 15 minutos/día     | Sincronizar el equipo: ¿Qué hice? ¿Qué haré? ¿Qué me bloquea? |
| **Sprint Review**   | 1-2 horas           | Mostrar avances al cliente.                                          |
| **Retrospectiva**   | 1-2 horas           | Mejorar procesos para el próximo sprint.                            |

### **Artefactos**

| **Artefacto**       | **Descripción**                  | **Ejemplo**                                |
| ------------------------- | --------------------------------------- | ------------------------------------------------ |
| **Product Backlog** | Lista de funcionalidades deseadas.      | "Generar PDF con sello DGI", "Exportar a Excel". |
| **Sprint Backlog**  | Tareas seleccionadas para el sprint.    | "Validar TXT para DGI (8 puntos)".               |
| **Incremento**      | Producto funcional al final del sprint. | App que genera facturas válidas.                |

---

## **3. ¿Qué es Planning Poker?**

**Definición**: Técnica para estimar la complejidad de tareas usando consenso y una escala de números (Fibonacci).

**Metáfora**:

> Es como preguntar a varios **vendedores del mercado** cuánto cuesta hacer un nacatamal. Cada uno da un precio, y se acuerda uno justo.

---

## **4. Cómo Hacer Planning Poker: Paso a Paso**

### **Materiales**

- Baraja de cartas: 0, 1, 2, 3, 5, 8, 13, 20, 40, 100, ∞, ?.
- Tareas del backlog (ej.: "Integrar envío de SMS con Claro").

### **Pasos**

1. **Presentación de la Tarea**:
   - *PO*: "La app debe enviar SMS al emitir facturas. Claro/Tigo tienen APIs con poca documentación".
2. **Preguntas Técnicas**:
   - "¿Hay ejemplos de integración exitosa?"
3. **Votación Secreta**:
   - Cartas reveladas: 5, 8, 8, 13.
4. **Discusión**:
   - *Argumento para 5*: "Ya usé la API de Claro".
   - *Argumento para 13*: "Sin soporte técnico en Nicaragua".
5. **Consenso**: Todos eligen **8 puntos**.

## **5. Práctica**

### **a) Juego de Roles (Role-Playing)**

**Ejercicio**: Simular un sprint para una app de ventas de café:

- **Tarea**: "Exportar reportes de ventas en Excel".
- **Pasos**:
  1. **PO** explica la importancia para caficultores.
  2. **Equipo** debate dependencias (ej.: formato de columnas).
  3. **Votación** con cartas hechas a mano.

### **b) Tabla de Complejidad con Ejemplos Locales**

| **Puntos** | **Complejidad** | **Ejemplo en Nicaragua**     |
| ---------------- | --------------------- | ---------------------------------- |
| **1**      | Muy fácil            | Cambiar color de un botón.        |
| **8**      | Complejo              | Generar TXT para DGI sin API.      |
| **13**     | Muy complejo          | Sistema de respaldo ante apagones. |

### **c) Actividad Práctica: Simulación de Sprint**

**Proyecto**: App para gestionar ventas de artesanías en Granada.

1. **Crear Backlog**:
   - "Login seguro", "Registro de ventas", "Generar facturas".
2. **Sprint Planning**:
   - Seleccionar tareas para 2 semanas (ej.: 20 puntos).
3. **Daily Standup**:
   - "Ayer trabajé en el login. Hoy, validaré con la DGI. Me bloquea la falta de API".

## **6. Evaluación del Aprendizaje**

### **Examen Teórico**

1. ¿Qué rol prioriza tareas en Scrum?a) Scrum Master  b) Product Owner  ✅  c) Equipo Dev.
2. ¿Por qué usar Fibonacci en Planning Poker?
   - Para reflejar incertidumbre en estimaciones.

### **Examen Práctico**

**Caso**: Un equipo estimó 8 puntos para una tarea, pero tardó el doble.
**Análisis**: No consideraron falta de soporte técnico local.

---

## **7. Conclusión**

Scrum y Planning Poker son herramientas para gestionar proyectos en entornos desafiantes, como Nicaragua. Al practicar con ejemplos locales y técnicas interactivas, los equipos pueden:

- Priorizar tareas críticas (ej.: cumplir con la DGI).
- Anticipar riesgos (falta de APIs, cambios normativos).
- Entregar valor de manera constante.
